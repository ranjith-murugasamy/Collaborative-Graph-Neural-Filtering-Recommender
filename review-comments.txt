[R1.1] Mathematical Formulation
--------------------------------------------------------------------------------
COMMENT:
  "Clearly define all equations, variables, graph construction, community
  detection, edge reduction, and training procedure."

STATUS: IMPLEMENTED

APPROACH:
  No runnable reference implementation of CGNF exists -- only the paper's
  equations (1)-(17) and three pseudocode algorithms, several with OCR-garbled
  or reused subscripts. Rather than reproduce that ambiguity, backend/app/
  graph.py and backend/app/edge_reduction.py implement one concrete, documented
  reading of each equation, function by function:

  - Eq. (1)-(2): bipartite modularity in the style of Barber (2007) -- observed
    link weight minus a degree-product null-model term, summed over
    same-community node pairs.
  - Eq. (3): ratings row-normalized per user, thresholded into "strong"
    (saturates to 1.0) vs. "weak" (kept fractional) links -- CGNF's one
    genuinely custom weighting step.
  - Eq. (4)-(11), Algorithm 1: community assignment via bipartite spectral
    co-clustering (Dhillon, 2001) -- the top-(H-1) singular vectors of the
    normalized bipartite link matrix embed users and items into a shared
    space, k-means'd into H communities. An initial literal reading of
    Eq.(15)-(17) as an alternating power-iteration update was tried first and
    found, via this project's own multi-seed validation feature, to collapse
    to a single community regardless of H -- see "Issues found independently"
    below.
  - Eq. (12)-(14): the modularity score (blending a local hard-assignment term
    and a global membership-confidence term) used to pick the community count H.
  - Algorithm 2 (edge reduction): vectorized subset-redundancy removal within
    each community, not a literal RL-wide pairwise loop.
  - Algorithm 3 (recommendation): community-scoped, similarity-weighted
    neighbor aggregation.

  One honest, named deviation: the paper's own H_max = (|V|*|L|)^0.5 bound
  evaluates to approx. 4,700 at MovieLens-1M's training-graph scale --
  exhaustively sweeping that many community counts is not tractable in
  minutes on CPU. This implementation sweeps a practical grid
  ([4,8,12,16,24,32,48,64]) instead and documents the gap explicitly
  (specs/spec.md section 2) rather than silently using a different bound
  without saying so.

[R1.2] Experimental Setup
--------------------------------------------------------------------------------
COMMENT:
  "Clearly specify datasets, preprocessing, data splits, negative sampling,
  evaluation method, hyperparameters, and random seeds."

STATUS: IMPLEMENTED

APPROACH:
  Every item is explicit, editable in the Train form, and recorded with every
  run:
  - Dataset: MovieLens 1M -- 6,040 users, 3,883 movies, 1,000,209 ratings.
  - Preprocessing/split: per-user, time-ordered leave-k-out (k=1 default);
    users with <= min_interactions stay entirely in train.
  - Negative sampling: used in BPR-MF's and LightGCN's training loss (uniform
    random negatives, resampled per batch) -- not at evaluation time, where
    candidates are the full remaining catalog.
  - Evaluation method: Recall@K / NDCG@K, K in {20,50}, per held-out user,
    averaged only over users with >=1 relevant held-out item (3,563 of 6,040).
  - Hyperparameters: every field in backend/app/runner.py's DEFAULTS is a
    visible Train-form input, not a hidden constant.
  - Random seed: an explicit seed field (default 0) on every run config.

[R1.10] Efficiency / Edge Reduction
--------------------------------------------------------------------------------
COMMENT:
  "Prove the efficiency claim using edge count, runtime, memory, and
  computational cost before and after edge reduction."

STATUS: IMPLEMENTED

APPROACH:
  Measured, not asserted. This run: edge reduction removed 7,115 of 994,169
  edges (0.72%), and took 10.6s with reduction vs. 9.8s without (wall-clock,
  full H-sweep + reduction step).

  HONEST CAVEAT: the edge-count reduction at this dataset's scale is modest
  (0.7%, not a dramatic fraction), and reduction adds wall-clock time in
  this implementation rather than saving it -- the "boosts computational
  efficiency" claim in the original abstract does not hold for this
  reproduction at this scale, at least not for the redundancy criterion as
  specified in Algorithm 2 (near-subset item sets are simply uncommon in a
  sparse, mostly-distinct-taste real dataset). This is reported as measured,
  not adjusted to match the original claim.

[R1.11] Ablation Study
--------------------------------------------------------------------------------
COMMENT:
  "Test the individual contribution of modularity, community detection,
  edge clustering/reduction, and GNN/NCF components."

STATUS: IMPLEMENTED

APPROACH:
  CGNF's own internal pipeline -- weighted modularity (Eq. 3-4) and edge
  reduction (Algorithm 2) -- is independently toggleable from one shared
  cgnf.fit() function (not four separately-maintained code paths), producing
  a real 4-way ablation:

    Configuration                        NDCG@20   Recall@20   Edges kept/before
    ------------------------------------ --------  ----------  ------------------
    CGNF - both (plain community CF)      0.0677    0.1622      994,169 / 994,169
    CGNF - weighted modularity              0.0676    0.1631      986,505 / 994,169
    CGNF - edge reduction                    0.0709    0.1715      994,169 / 994,169
    Full CGNF                                 0.0707    0.1726      987,054 / 994,169

  Findings: WEIGHTED MODULARITY MATTERS (0.0707 full vs. 0.0676 unweighted,
  +4.6% -- the single biggest ablation gap); EDGE REDUCTION DOES NOT HELP
  ACCURACY at this scale (0.0707 with it vs. 0.0709 without, -0.2% --
  CGNF's weakest component by this measure, matching R1.10's finding) while
  removing 0.7% of edges and costing more wall-clock than it saves.

[R2.5] Statistical Validation
--------------------------------------------------------------------------------
COMMENT:
  "Report results from multiple runs with different random seeds,

STATUS: IMPLEMENTED

APPROACH:
  backend/app/stats.py re-trains CGNF and the strongest baseline across N
  seeds (default 5, paired -- same seeds for both methods), reports mean +/-
  SD, and runs a paired t-test (always) plus a Wilcoxon signed-rank test
  (when >=6 non-tied pairs exist).

  REAL MULTI-SEED RESULT, this run (NDCG@20, seeds 0-4):

    Method              Seed0    Seed1    Seed2    Seed3    Seed4    Mean +/- SD
    ------------------  -------  -------  -------  -------  -------  -----------------
    CGNF (proposed)       0.0707   0.0712   0.0703   0.0704   0.0716   0.0708 +/- 0.00054
    Item-kNN                0.0628   0.0628   0.0628   0.0628   0.0628   0.0628 +/- 0.0000

  Item-kNN's exact-zero standard deviation is CORRECT, not a bug:
  cosine-similarity Item-kNN has no stochastic component, so it is expected
  to be perfectly deterministic regardless of seed. CGNF's non-zero std
  (0.00054) confirms its k-means-based clustering step is now genuinely
  randomized per seed (see the bug-fix account under "Issues found
  independently" below).

  PAIRED T-TEST: t = 33.28, p = 4.86e-6 (n=5 paired seeds) -- CGNF's
  advantage over Item-kNN is statistically significant, not a single-run
  artifact.

  WILCOXON SIGNED-RANK: not computed -- only 5 non-tied pairs; this test
  conventionally needs >=6. Reported as unavailable rather than omitted
  silently.

Found independently: standard graph/GNN libraries install cleanly here,

--------------------------------------------------------------------------------
  Verified empirically: `pip install --dry-run networkx python-louvain

--------------------------------------------------------------------------------
Found in this project's own first implementation (not the paper):
community detection silently collapsed to a single cluster
--------------------------------------------------------------------------------
  An initial, literal reading of Eq.(15)-(17) as an alternating
  power-iteration update (two sparse matrix multiplications per iteration)
  was built, trained on real MovieLens-1M data, and looked plausible -- it
  produced a modularity score and ran end-to-end without error. It was
  only caught by this project's own multi-seed statistical-validation
  feature (built to satisfy Reviewer 2 item 5): 5 different random seeds
  produced BIT-IDENTICAL results, which is essentially impossible for a
  genuinely stochastic clustering procedure. Direct investigation confirmed
  every tested community count H in {4,8,16,32,64} collapsed to exactly
  ONE occupied community regardless of the target H -- a textbook failure
  mode of repeated multiplication by a positive matrix on a single
  connected graph (it converges toward the dominant eigenvector, not H
  distinct clusters).

  FIX: replaced with bipartite spectral co-clustering (Dhillon, 2001) -- the
  top-(H-1) singular vectors of the normalized bipartite link matrix,
  k-means'd into H clusters. Verified fixed: every H now produces exactly H
  non-empty communities with varied sizes (e.g. H=4 -> sizes
  [2095, 1726, 1403, 816]), and 5 different seeds now produce genuinely
  different (but statistically consistent) results -- CGNF's multi-seed
  NDCG@20 has mean 0.0708, std 0.00054, vs. the earlier version's
  impossible std of exactly 0.0.

  WHY THIS IS REPORTED AT ALL: every number in this document comes from the
  fixed version, not the broken one -- this entry exists because the same
  honesty standard this document holds the original paper to has to apply
  to this implementation's own mistakes, including ones that were caught
  and fixed before anyone outside this project ever saw them.
